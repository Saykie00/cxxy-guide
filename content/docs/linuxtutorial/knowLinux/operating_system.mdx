我们可以先对我们每天都面对着的电脑和手机做一个区分。
~~*他们都是计算机*~~(bushi)
计算机如果没有操作系统，那么我们就无法使用它。这听起来可能有些危言耸听，但事实确实如此。如果不使用操作系统而直接面对裸机（Bare Metal）进行开发，所需要的工程量远远大于一个人能够达到的极限。你需要通过复杂的二进制代码或汇编语言去直接控制每一个硬件开关，管理每一字节的内存，这在实际应用中几乎是不可能完成的任务。

在计算机诞生之初，并没有一个统一的操作系统概念，每台计算机往往都配备有一个独一无二的操作系统。于是这里就产生了一个巨大的问题：不同系统编译出来的程序无法相互兼容运行。这就像今天的安卓软件无法直接在Windows电脑上使用一样，软件的移植和复用变得异常困难。

### 操作系统简要历史


关于操作系统的统一化，有一个著名的故事。故事的启示源于一个叫做**肯·汤普逊**（Ken Thompson）的天才程序员。他在贝尔实验室的大型计算机上发明了一门计算机编程语言，叫做B语言（C语言的前身），并使用B语言写了一个太空旅行的游戏。但是，当那台大型计算机被搬走后，他只能在实验室里面找到几台性能较弱的小型计算机（PDP-7）。他发现这样太麻烦了，为了让游戏在不同的电脑上运行，他必须在不同的电脑之间反复重新编译代码，适配不同的硬件。为了解决这个痛点，他和团队（包括丹尼斯·里奇等人）最终写出了第一版UNIX系统。UNIX的出现，标志着操作系统开始走向标准化和可移植化。

后来，操作系统的世界迎来了百花齐放的时代。


### 主流的操作系统


Linux系统是这个领域中不可忽视的巨人。这个系统并不高深，甚至可以说它非常亲民，虽然我们时时刻刻都在使用Linux系统，但我们往往不自知。更准确来说，我们使用的是GNU/Linux，但我们现在习惯直接简称为Linux。由于它是开源的，这意味着它的源代码对所有人开放，因此有着大量的“发行版”。比如Ubuntu、CentOS、Debian等，它们就像是用同一个引擎（内核）组装出的不同品牌的汽车。Linux广泛应用于我们的生活中：从支撑互联网运转的超级服务器，到个人的开发环境，甚至是你家里的智能电视和路由器，背后都有Linux的身影。

Android系统，也就是我们熟知的安卓系统，本质上也是基于Linux内核开发的系统。它常用于智能手机、平板电脑等移动设备。相对于完全开源的Linux发行版，Android是相对开源的（核心开源，但上层服务闭源），它是谷歌（Google）推出的系统，凭借其开放性占据了移动操作系统的半壁江山。

Windows系统（~~史？！~~），由微软（Microsoft）推出，是现代个人电脑最主流的操作系统。它最大的特点是极致的兼容性，几乎所有的硬件厂商都会为Windows提供驱动，几乎所有的软件开发者都会优先开发Windows版本。它是一个典型的闭源商业系统，凭借图形用户界面的普及，让计算机真正走进了千家万户。

macOS，是苹果公司用于Mac系列电脑的专用系统。它同样也是闭源的，以其精美的界面设计、优秀的色彩管理和稳定的Unix内核著称，深受设计师和程序员的喜爱。

iOS，则是苹果公司用于iPhone手机或者iPad平板电脑的操作系统。它与macOS一脉相承，也是闭源系统，以流畅的体验和严格的安全管控闻名于世。

当然，这个世界上还有各种其他的系统，比如华为的鸿蒙系统（HarmonyOS）、用于嵌入式设备的实时操作系统等，但由于篇幅原因或因为它们太不主流，这里就不做详细阐述了。


### 用户态与内核态


既然我们已经认识了操作系统这个负责管理计算机资源的“大管家”，那么一个很自然的问题便出现了：

**普通程序为什么不能随意访问计算机中的所有资源？**

例如，当一个游戏发生错误时，我们通常只需要关闭游戏，而不应该因此导致整个操作系统崩溃。一个文本编辑器也不应该能够随意读取其他程序的内存，更不能直接修改操作系统正在使用的数据。

要实现这种隔离，就需要操作系统提供一种基本的权限边界：**用户态（User Mode）与内核态（Kernel Mode）**。

在现代操作系统中，处理器通常提供不同的特权级别。操作系统内核运行在具有较高权限的环境中，而普通应用程序则运行在受限制的用户态。

处于用户态的程序不能直接执行所有特权操作，也不能随意访问硬件和其他程序的内存。如果一个程序需要执行这些操作，就必须通过操作系统提供的接口，请求内核代为完成。

例如，一个程序想要读取文件，并不是直接控制硬盘上的存储介质，而是向操作系统发出文件读取请求。内核检查权限并完成相应的操作，再将结果返回给程序。

这个过程可以简单地理解为：

> **应用程序提出请求 → 内核检查并执行 → 将结果返回给应用程序。**

这种隔离是现代操作系统可靠性和安全性的基础之一。

如果普通程序拥有与内核相同的权限，那么任何程序中的错误都可能影响整个系统。一个简单的指针错误，就可能覆盖其他程序的数据；一个恶意程序，也可能直接修改系统关键资源。

而在用户态与内核态之间建立边界之后，普通程序出现故障时，影响通常会被限制在自身的运行环境中。浏览器崩溃了，通常只是浏览器进程退出，而不是整个操作系统随之停止工作。

当然，这并不意味着“用户态程序永远无法让系统崩溃”。内核本身、驱动程序以及硬件仍然可能出现问题。但从系统设计的角度来看，**权限隔离为这种故障提供了一道重要的防线。**

### 单用户与多用户系统



前面讨论的是**程序之间的隔离**，接下来再进一步考虑一个问题：

**不同的使用者之间，应该如何共享一台计算机？**

这便涉及操作系统中的用户（User）与多用户（Multi-user）概念。

所谓多用户系统，并不是简单地指“一台电脑上可以创建多个账户”。更重要的是，操作系统能够识别不同的用户，并为他们分别管理文件、进程以及其他系统资源。

例如，在一台 Linux 服务器上，可能同时存在多个用户。用户 A 可以拥有自己的文件和进程，用户 B 也拥有自己的文件和进程。操作系统需要确保用户 A 默认不能随意读取用户 B 的私人文件，也不能直接终止属于其他用户的进程。

这就要求操作系统建立一套完整的**身份与权限机制**。

早期的个人计算机系统中，单用户环境比较常见。例如 MS-DOS 的设计主要面向单个使用者。随着操作系统的发展，多用户机制逐渐成为服务器和通用操作系统的重要组成部分。

需要注意的是，**“单用户”和“多用户”并不等同于“一个人使用”或“几个人同时坐在电脑前”。**

一台个人电脑完全可以拥有多个用户账户；而一台服务器上的多个用户，也可以通过网络同时使用同一台机器。这里真正重要的是操作系统是否能够对不同用户的身份、资源和权限进行独立管理。

Linux 继承了 Unix 系统中成熟的多用户设计。我们之后会接触到的用户、用户组、文件权限、进程权限等概念，都与此密切相关。

因此，当你第一次看到 Linux 中的：

```text
user
group
owner
permission
root
```

它们并不是一些为了增加学习难度而存在的概念，而是操作系统进行资源隔离与管理的基础。

其中 `root` 用户拥有极高的系统权限，也正因为如此，Linux 中经常会提醒你：

> **权限越大，能做的事情越多，能造成的破坏也越大。**

例如这个代码
```
请千万不要执行此命令，它会删除你电脑中的所有数据！！！
请千万不要执行此命令，它会删除你电脑中的所有数据！！！
请千万不要执行此命令，它会删除你电脑中的所有数据！！！
sudo rm -rf /*
```

所以，不要因为终端里出现了 `root` 就觉得自己突然成为了计算机的主人——内核仍然比你更了解这台机器。

### Unix 与 Linux 的关系


了解了操作系统的基本结构之后，我们再来解决另一个经常让 Linux 初学者感到困惑的问题：

**Unix 和 Linux 到底是什么关系？**

最简单的说法是：

> **Linux 不是 Unix，但 Linux 是一个类 Unix（Unix-like）操作系统。**

Unix 起源于 1969 年的贝尔实验室。肯·汤普逊（Ken Thompson）、丹尼斯·里奇（Dennis Ritchie）等人参与了早期 Unix 的开发。

Unix 的重要意义并不只是它本身是一套操作系统，更在于它形成了一套影响深远的系统设计思想与接口传统。例如，将许多系统资源抽象为文件、使用小型工具组合完成复杂任务，以及通过统一的接口与操作系统交互等思想，都对后来的操作系统产生了深远影响。

随着 Unix 的发展，出现了许多不同的 Unix 系统和实现，例如 IBM 的 AIX、HP 的 HP-UX，以及后来由 Berkeley 发展出的 BSD 系列。

与此同时，Unix 的商业化也使得普通个人用户较难直接接触到完整的 Unix 系统。

1991 年，芬兰学生 Linus Torvalds 开始开发一个新的操作系统内核。这个内核并不是从 Unix 源代码修改而来，而是一个独立实现，但它在设计上受到了 Unix 系统和 Unix 设计思想的明显影响。

这个内核后来被称为 **Linux**。

因此，两者之间的关系并不是简单的“Linux 是 Unix 的一个版本”，也不是“Linux 复制了 Unix 的代码”。

更准确地说：

> **Unix 是一个历史悠久的操作系统家族及其相关标准体系，而 Linux 是一个独立开发、采用了许多 Unix 设计思想并遵循大量 Unix 传统接口的内核。**

这也是为什么我们会称 Linux 为 **Unix-like**，即“类 Unix”。

如果一定要用一个不那么严肃的比喻，那么可以说：Unix 更像是一位历史悠久的前辈，而 Linux 并不是继承了前辈源码的后代，而是一个受其思想影响、走出了自己道路的后来者。

今天，我们仍然可以在服务器、超级计算机、嵌入式设备以及 Android 等系统中看到 Linux 内核的身影；而 Unix 的思想与接口传统，则已经广泛影响了现代操作系统。
