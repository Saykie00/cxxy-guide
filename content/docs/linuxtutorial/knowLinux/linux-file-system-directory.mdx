# 目录结构

与我们所熟知的 Window 不同，Linux 的目录结构采用倒置的树状结构。所有的文件和目录皆是从唯一的 `/` 目录开始的。  

所有文件和目录都挂载在唯一的根目录 `/` 下。它遵循 [FHS标准](https://en.wikipedia.org/wiki/Filesystem_Hierarchy_Standard) (文件系统层次结构标准)，统一管理系统资源，不像Windows有C盘、D盘之分。核心目录包括 `/etc` (配置)、`/bin` (基本程序)、`/home` (用户主目录) 和 `/var` (日志数据)。  

以及，FHS标准其实是一种规范，而非强制执行的代码约束什么的，开发者和用户可以选择不遵守，但是那样会增加额外的维护成本，不便于管理。  

以及很多自动化的工具都是默认基于FHS标准进行的，如果用户不遵守规范，这些工具可能失效，或者需要用户写大量的自定义配置。~~*（你也不想让你的文件被自动化清理脚本删除吧）*~~

Linux 目录结构总览  

`/` : 根目录,所有目录都是挂在在根目录下  
	 **`/root`**：系统管理员（超级用户）的家目录。  
	 **`/bin`**：存放基本的用户二进制文件（命令），所有用户可用。  
	 `/sbin`：存放基本的系统二进制文件（系统管理员命令）。  
	 **`/etc`**：所有系统配置文件，控制系统程序的行为。  
	 **`/dev`**：设备文件，包含所有硬件设备，如 `/dev/sda` (硬盘)。  
	 `/proc`：虚拟文件系统，包含当前运行的内核信息和进程信息。  
	 `/var`：存放经常变动的文件，如日志文件 `/var/log`。  
	 `/tmp`：临时文件，系统启动或程序运行时产生，重启时可能会清除。  
	 **`/boot`**：存放启动Linux系统所需的核心文件，包括Linux内核。  
	 `/lib`：基本共享库和内核模块  
	 `/mnt`：管理员用于临时挂载文件系统的目录。  
	 **`/media`**：用于挂载可移动设备，如U盘、光驱。  
	 `/opt`：可选的应用程序软件包安装目录  
	 **`/home`**：普通用户的主目录，例如 `/home/Saki酱😭`  
	 **`/usr`**：包含所有用户程序、库、文档的目录（最大的目录之一）。  
	  `/usr/bin`：用户程序的二进制文件。  
加粗为较为使用频率较高的目录  
# 文件系统

文件系统在很多情况下都有所涉及，比如NTFS格式的U盘在 Window 上可以正常的读写，但是默认插到 macOS 上却不能写入，只能只读。  

物理文件系统的诞生源于解决磁盘存储的“地址空间”和“名字空间”问题，它的发展经历了从单机文件系统到分布式文件系统的演化，逐步满足了数据量不断增长和访问效率提升的需求。  

磁盘的线性地址空间问题：磁盘本质上是连续的线性空间（LBA0到LBA N），但文件往往无法连续存储，删除后会产生“碎片”。需要软件来管理逻辑连续性与物理分散性。  

文件查找问题：随着文件数量增加，必须有目录、子目录和路径来组织和索引文件，方便用户快速定位。  

因此，文件系统应运而生，负责 空间管理（分配与释放）、逻辑组织（目录结构）、访问接口（读写操作）  

一个合格的文件系统包括分区表（MBR、GPT）、超级块、inode、目录结构、数据块、日志系统、空间管理器。
常见的文件系统包括  
`Btrfs`,
`FAT32(vFAT)`,
`Ext4`,
`XFS`,
`F2FS`,
`ZFS`,
`exFAT`,
`NTFS`

我们只挑最常接触的来说。  

#### Btrfs

Btrfs在Arch、Fefora等发行版用户中受到了普遍的欢迎，因为它解决了传统文件系统（如 Ext4）难以实现的数据一致性、动态扩展和极速备份问题  

Btrfs有以下优势  
- **快照（Snapshots）与回滚**：利用 Btrfs，你可以在更新系统前秒级创建一个镜像。如果更新导致系统崩溃，你可以直接进入旧快照，瞬间恢复到之前的状态。  
- **透明压缩**：它支持在数据写入磁盘前自动进行 zstd 或 lzo 压缩。这不仅节省空间，由于减少了 I/O 写入量，还能显著提高 SSD 的寿命和读取速度。  
- **子卷（Subvolumes）管理**：你可以在一个大分区里划分多个子卷，它们共享同一个分区的总空间，无需像传统分区那样预先分配死空间。  
- **自修复（Self-healing）**：它会为所有数据和元数据计算校验和。如果发现硬盘扇区数据损坏，它可以利用冗余数据自动修复。  

Btrfs 的强大主要源于以下三个底层机制：  


**A. 写时复制 (CoW - Copy on Write)**  

这是 Btrfs 最本质的特性。  

- **传统逻辑**：修改文件时，直接在原有数据的物理位置上覆盖写入。  
- **Btrfs (CoW) 逻辑**：修改文件时，不改动原始数据。它将修改后的数据写入磁盘的一个**新位置**，待写入成功后，再更新文件系统的指针指向新位置。  
- **结果**：即使在写入过程中突然断电，旧数据依然完整，文件系统永远不会处于“写了一半”的损坏状态。  

**B. 基于 B-Tree 的元数据组织**  

顾名思义，Btrfs 几乎所有的内部结构（包括索引、inode、文件数据）都组织成 **B-Tree** 结构。  

- 这种结构使得文件查找、扩展和删除操作在海量小文件或超大容量磁盘下依然保持极高的效率。  
- **子卷和快照**在底层其实只是指向同一棵树的不同“根节点”。创建快照时，它只是复制了一份树根的指针，而没有物理复制任何数据。  

**C. 校验和 (Checksumming)**  

Btrfs 会对每一块存入的数据生成一个 CRC32C（或更高级的）校验值。  

- 读取数据时，系统会重新计算校验值并与元数据对比。  
- 如果值不匹配，说明硬件出现了数据腐烂（Silent Data Corruption）。如果是 RAID 模式，它会立即从另一个镜像副本中读取正确数据并修复损坏部分  

#### Ext4  

Btrfs 追求先进功能不同，Ext4 的核心目标是极致的稳定性**和**高性能的基准表现。  

所以Ext4（Fourth Extended Filesystem）是目前 Linux 领域最成熟、使用最广泛的原生文件系统。它是许多主流发行版（如 Debian、Ubuntu、CentOS）的默认选择。  

**Ext4 的核心特性**  

- **日志功能（Journaling）**：这是其稳定性的基石。在数据正式写入磁盘前，会先记录在日志区。如果发生意外断电，系统可以通过扫描日志快速恢复文件系统的一致性，而不需要进行耗时的全盘扫描（fsck）。  
- **巨大的存储限额**：  
    
    支持最大 **1 EB** ($10^{18}$ 字节) 的分区。  
    
    支持最大 **16 TB** 的单文件。  
    
- **区段（Extents）机制**：  
    
    **原理**：传统文件系统（如 Ext3）通过“映射表”记录每个数据块的位置。Ext4 则改用“起始块 + 长度”的方式记录一段连续的数据块。  
    
    **优点**：大幅减少了元数据开销，显著提升了处理大文件的效率，并减少了磁盘碎片。
    
- **延迟分配（Delayed Allocation）**：
    
    数据在程序发起写指令时不会立刻写入磁盘，而是先存在内存缓冲区。
    
    等到缓冲区快满时，内核再统一分配物理块并写入。这样可以尽量让文件数据在磁盘上连续存储，提升读取性能。  

#### NTFS  

**NTFS**（New Technology File System）是微软开发的专有文件系统，自 Windows NT 3.1 以来一直是 Windows 系列的默认格式。  

**核心技术特性**  

- **日志式文件系统（Journaling）**：与 Ext4 类似，NTFS 通过记录操作日志来防止由于掉电导致的文件系统结构损坏。  
- **复杂的权限控制（ACL）**：支持细粒度的访问控制列表（Access Control Lists），但这套权限逻辑与 Linux 的 UID/GID 权限模型完全不兼容。  
- **高级功能**：  
    - **磁盘配额**：限制用户使用的空间。  
    - **透明压缩**：虽然不如 Btrfs 的 zstd 高效，但能节省空间。  
    - **符号链接与硬链接**：支持类似 Unix 的链接机制。  
    - **MFT（Master File Table）**：核心数据库，记录了磁盘上所有文件的元数据。

 **Linux 对 NTFS 的支持演进**  


在 Linux 下挂载 NTFS 分区经历过三个主要阶段：

1. **早期内核驱动**：仅支持读取，写入极不稳定，容易导致分区损坏。  
2. **NTFS-3G（FUSE）**：长期以来的标准方案。它在“用户态”运行，稳定性高，支持读写，但由于数据要在内核和用户空间之间多次转换，**性能较差**，CPU 占用率高。  
3. **NTFS3 内核驱动**：由 Parrot 公司开发并于 2021 年并入 Linux 5.15 内核。它直接在**内核态**运行，读写性能大幅提升，接近原生速度。  

**以及，我们该在何时使用NTFS？**  

答案是除了在Window上使用NTFS，其他的任何地方都不要使用它  
你猜猜 Window 有没有第三方驱动使得 Window 能够对使用了 Btrfs 文件系统或 Ext4 文件系统的磁盘进行读写？~~*都用Window了，那点性能开销无所谓吧*~~  

#### FAT

**FAT**（File Allocation Table，文件分配表）是计算机历史上最经久不衰的文件系统格式。它由微软在 20 世纪 70 年代末开发，最初用于软盘，后来演变为多种版本。  

在 2026 年的今天，尽管它技术落后，但在**跨平台兼容性**和**嵌入式系统**中仍具有不可替代的地位。

FAT12 诞生于软盘时代，太老了不讲  
FAT16 诞生于MS-DOS时代，太老了不讲  
FAT32 主要用于EFI 分区 (ESP)、U 盘、SD 卡。单文件最大 4GB，分区最大理论 2TB  
exFAT 现代移动存储  

**核心工作原理：文件分配表**

FAT 的核心是一个简单的索引表。

- **文件存储**：数据被分成若干个“簇”（Cluster）存放在磁盘上。由于文件往往不是连续存储的，FAT 表记录了这些簇之间的链式关系。  

- **读取过程**：系统先在目录项中找到文件的第一个簇号，然后去 FAT 表中查：第一个簇之后是哪个？第二个之后又是哪个？直到读到结束标记。  

- **结构简单**：它没有 Ext4 的 inode 概念，也没有 NTFS 复杂的权限管理，元数据开销极小。  

**为什么它在 Linux/现代系统里还没死？**

- **UEFI 标准的强制要求**：所有的 UEFI 固件都只能识别 FAT32。因此，无论你的 Linux 根目录是 Btrfs 还是驱动多么先进，**EFI 系统分区（ESP）必须是 FAT32**。  

- **极高的兼容性**：它不需要复杂的内核驱动。几乎任何单片机（如 Arduino、STM32）或极简系统都能轻松读写 FAT32 数据。  

- **资源消耗极低**：由于逻辑简单，它对内存和 CPU 的要求几乎可以忽略不计。  

以及，除了U盘之外，和EFI分区或者其他必须要使用该文件系统之外，请最好不要使用FAT
